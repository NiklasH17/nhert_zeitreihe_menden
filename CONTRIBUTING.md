
## Branches

- Niemals direkt auf `main` pushen – immer einen eigenen Branch erstellen
- Branch-Namen beschreiben was man tut: `feature/login`, `fix/crash-on-start`
- Branch nach dem Merge löschen

## Commits

Kurz und klar beschreiben was gemacht wurde:

```
feat: Login-Seite hinzugefügt
fix: Absturz beim Starten behoben
docs: README aktualisiert
```

## Pull Requests

- Einen PR erstellen wenn man fertig ist. Kein direkter Push auf `main`
- Kurz beschreiben was du geändert wurde und warum
- Mindestens eine Person muss den PR freigeben, bevor er gemergt wird

## Code Review

- Feedback annehmen und entweder umsetzen oder kurz erklären warum nicht
- Fragen stellen statt raten

## Sonstiges

- Keine Passwörter oder Secrets ins Repo `.env`-Datei nutzen
- Tests nicht vergessen
- Bei Fragen einfach fragen
